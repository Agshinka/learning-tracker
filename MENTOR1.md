## Git — reset vs revert — практика — закрыто 24.09.2026
**Разобрали:** revert на конфликтующем коммите (маркеры + revert --continue), разница revert --continue vs обычный commit при уже разрешённом конфликте, reset --soft/--mixed/--hard на реальных коммитах, HEAD~1 синтаксис
**Усвоено твёрдо:** revert может конфликтовать так же, как merge, если контекст вокруг строки изменился; --soft/--mixed/--hard — нарастающая степень разрушительности (staged → рабочая директория → нигде); --hard удаляет безвозвратно (параллель с rm -r); revert не трогает историю, добавляет новый коммит поверх — безопасен для общих веток, --hard — нет
**Шатко:** —
**Не тронули:** —
**Практика:** полный цикл руками, включая реальную путаницу (двойной revert, забытый git add перед --continue, опечатка HEAD-1 вместо HEAD~1) — разобрано и исправлено по ходу, не просто пройдено гладко

## Git — remote/pull + Pull Request — практика — закрыто 25.09.2026
**Разобрали:** pull перед началом работы, создание ветки при уже незакоммиченных изменениях, ошибку "ветка создана после коммита вместо до" и её исправление через reset --hard origin/main без потери коммита, push -u, открытие и мерж PR на GitHub, pull после мержа, удаление отработавшей ветки
**Усвоено твёрдо:** коммит — физический объект с хэшем, ветка — просто указатель на него; несколько указателей могут смотреть на один коммит одновременно, поэтому reset --hard безопасен, если коммит ещё достижим с другой ветки; порядок важен — ветку создают до правок, которые должны в неё попасть, а не после
**Шатко:** —
**Не тронули:** —
**Практика:** полный цикл руками на реальном репозитории, включая реальную ошибку с порядком (коммит на main вместо ветки) и её самостоятельное исправление под руководством, реальный PR с ревью diff, реальный мерж, реальное удаление ветки
